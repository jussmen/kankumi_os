# ADR 0001: 管理者入力の PaymentProfile を住民入力より優先する

## Status
Accepted

## Context
各 Unit には、BankTransaction の自動マッチングに使用する PaymentProfile（振込名義・銀行名・口座番号下4桁）が必要。この情報は住民（Unit の居住者・所有者）が自身でSaaSに登録することを基本とするが、ITリテラシーが低い高齢者など、自己登録が困難なケースが存在する。そのため管理者（理事・会計担当）が代わりに入力できる仕組みが必要となる。

同一 Unit に住民入力と管理者入力の両方が存在する場合、どちらをマッチングに使用するかを決める必要がある。

## Decision
同一 Unit に source = `admin` の PaymentProfile と source = `user` の PaymentProfile が共存する場合、**管理者入力（admin）を優先**してマッチングに使用する。

## Consequences
- **メリット**: 管理者が誤った住民入力を修正・上書きできる。リテラシーの低い住民への対応が可能。
- **デメリット**: 住民が自分の情報を更新しても、管理者入力が残っている限り反映されない。住民への説明・UIでの明示が必要。
- **必要なUI対応**: 管理者入力が存在する場合、住民の画面にも「管理者が情報を設定済み（変更は管理者に連絡）」と表示する。
